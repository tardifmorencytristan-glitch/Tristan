# Contributing

Changes to `Tristan` should preserve the smallest sufficient kernel and must not promote claims beyond observed evidence.

## Required discipline

1. Search for an existing owner before adding a new primitive.
2. Keep generation, execution, verification, reality evidence, and authority separate.
3. Add or update tests for every behavioral change.
4. Record failures and negative results when they affect future routing.
5. Compare against a simpler baseline or `NO_ACTION` when extra complexity is proposed.
6. Treat a passing repository workflow as engineering evidence only, not scientific validation.
7. Preserve provenance and supersession lineage.

## Promotion states

Use explicit states such as `PROVISIONAL`, `SUPPORTED`, `MEASURED`, `VERIFIED_ENGINEERING`, `HOLD`, `REJECTED`, `SUPERSEDED`, and `RESIDUAL`.

No component receives preference because it originated inside Tristan.
