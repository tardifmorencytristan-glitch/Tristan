# Ω Multidirectional Omni Compiler — R2

Status: PROVISIONAL / EXECUTABLE LINEAGE + INVALIDATION KERNEL

R2 strengthens the R1 cross-domain path with content-addressed artifact identity, lineage, invalidation, richer transformation receipts and an exact GitHub-state adapter.

## Implemented

- `ArtifactIdentity` and `ArtifactGraph` with SHA-256 content identity, parents, receipt lineage and descendant closure.
- `InvalidationReceipt` and affected-closure computation: a changed upstream artifact invalidates its dependent descendants.
- R2 transformation receipts contain input/output hashes, operator version, authority, cost and risk.
- `GitHubStateAdapter` builds `GitIR` from observed branch/check payloads and refuses `PASS` when checks are absent, stale, incomplete or failing.
- Unit tests cover lineage, invalidation, receipt hashes and exact-head check semantics.

## Hard boundaries

- `HashEquality != SemanticTruth`.
- `GitHubPayloadRead != CodeCorrectness`.
- `ExactHeadChecksPASS != ScientificPASS`.
- `Invalidated != AutomaticallyRebuilt`.
- `ArtifactIdentity != ArtifactBytesVerified` unless bytes were actually read and hashed.
- `PDFSourceKnown != PDFReadbackPASS`.

## Closed-loop status

Implemented and tested:

`SPEC -> CODE -> GIT -> DOCUMENT -> ARTIFACT-CANDIDATE -> DOCUMENT`

plus content-addressed lineage/invalidation and exact GitHub state ingestion.

Still open for a true external closed loop:

`REAL PDF bytes -> reverse parse -> IR -> code/Git -> LaTeX -> rendered PDF -> visual/text readback -> reverse IR`.

That path must not be called complete until an actual PDF has been materialized, rendered, inspected and round-tripped.
